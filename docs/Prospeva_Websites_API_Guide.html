Prospeva Websites — API Guide

One document for the web developer. Exactly three panels: the Business panel (one site that serves 8 business types), the Employer panel and the Admin panel. Every call is in Prospeva_Websites.postman_collection.json (895 requests).

1. Read this first

Item Value
Local host http://localhost:2041
Render host https://mr-prospera-backend-kza5.onrender.com
Business panel base /api/v1/vendor
Employer panel base /api/v1/corporate
Admin panel base /api/v1/admin

Response shape on every call: { "status": 200, "message": "...", "data": { } }. Show message on any non-2xx.

Sign-in and tokens

Panel Sign-in call Token variable Send on every later call
Business (all 8 types) POST /api/v1/vendor/signin vendorToken Authorization: Bearer <token>
Employer POST /api/v1/corporate/signin corporateToken Authorization: Bearer <token>
Admin POST /api/v1/admin/signin adminToken Authorization: Bearer <token>

Sign-out revokes the session (POST /api/v1/vendor/signout). Forgot password is a three-call flow: forgetPassword (code sent by email) → forgotVerifyOtp (returns a reset token) → changePassword/:userId.

Maker-checker (all money-out in the Business panel)

Any money leaving a business (move funds, withdraw, supplier payment, payout from the mobile app) is created as a request. A second person with the approver permission approves it in Approvals. The balance is debited and the ledger written only on approval. Reject returns it to the maker with a reason. The same person cannot approve their own request.

Money and limits

Currencies LRD and USD (1 USD = 199.25 LRD in the Smart Route preview). Always call the review endpoint first: it returns fee, FX and total without moving money. Fees: Prospeva user 0%, bank 1%, mobile money 1%, international 2.5%, agent 0.5%.

2. Panel 1 — Business panel (8 business types)

One website, one login screen. The sign-in response carries the workspace type (Merchant, Lender, Hospital, School, Susu Group, Prospeva Agent, Church, Landlord). Build the shared modules once; show the type-specific modules only for the matching type. GET /api/v1/vendor/portal/session returns the type and the module list to render in the sidebar.

2.1 Who uses it

Role Can do
Owner Everything, including staff, roles, policy, approvals
Approver Approves or rejects maker requests
Finance / cashier Creates invoices, requests move funds, records payments
Viewer Reads dashboards, reports

Roles and limits come from GET /api/v1/vendor/organization/roles and the transaction policy (/organization/transactionPolicy).
